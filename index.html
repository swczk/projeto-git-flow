Boas Práticas para Repositórios Git

Padronização de Mensagens de Commit

A padronização de mensagens de commit é fundamental para manter um histórico claro e facilitar a revisão. O padrão Conventional Commits é altamente recomendado:

<tipo>[escopo opcional]: <descrição>

[corpo opcional]

[rodapé opcional]

Os tipos mais comuns são:

  • feat: nova funcionalidade
  • fix: correção de bug
  • docs: alterações em documentação
  • style: formatação de código
  • refactor: refatoração de código
  • test: adição/modificação de testes
  • chore: tarefas de manutenção

Exemplo: feat(auth): implementa autenticação com JWT

Esta padronização facilita a geração automática de changelogs e Semantic Versioning (SemVer).

Estrutura de Branches

A escolha da estrutura de branches deve considerar o tamanho da equipe e complexidade do projeto:

Git Flow: Ideal para projetos com ciclos de release definidos, mantendo branches:

  • master/main: código em produção
  • develop/dev: desenvolvimento contínuo
  • feature/*: novas funcionalidades
  • release/*: preparação para release
  • hotfix/*: correções urgentes

GitHub Flow: Mais simples, adequado para deploy contínuo:

  • main: sempre estável e pronto para deploy
  • feature/*: desenvolvimento de funcionalidades

Arquivos Essenciais

Todo repositório profissional deve conter:

  1. README.md: Primeira impressão do projeto, contendo:
    • Descrição e propósito
    • Instruções de instalação
    • Como executar e testar
    • Exemplos de uso
    • Status do projeto
  2. .gitignore: Evita commits de arquivos desnecessários como:
    • Arquivos de configuração local
    • Dependências instaladas
    • Arquivos compilados
    • Credenciais e segredos
  3. .dockerignore: Semelhante ao .gitignore, mas para builds Docker:
    • Evita que arquivos desnecessários sejam incluídos na imagem Docker
    • Reduz o tamanho da imagem e melhora o tempo de build
    • Previne vazamento de dados sensíveis
  4. CONTRIBUTING.md: Guia para contribuidores explicando:
    • Processo de submissão de PR
    • Padrões de código
    • Estrutura do projeto
    • Fluxo de trabalho
  5. LICENSE: Define como o código pode ser usado e distribuído.
